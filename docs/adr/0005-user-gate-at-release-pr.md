# 0005. 사용자 확인 지점: 작업 PR 이 아니라 릴리스 PR

- 상태: 채택(2026-11-25 개정 — 아래 "개정")
- 날짜: 2026-11-24
- 관련: ADR-0004, `.claude/rules/git.md`, `/pr` · `/release` 스킬

## 맥락
처음 역할 분담은 "PR 은 Claude 가 만들고 리뷰 코멘트를 남기며, 병합은 모두 사용자"였다. 작업 PR 마다 사용자가 확인·병합해야 해서 번거롭다는 의견이 나왔다. ADR-0004 에서 마일스톤 = 릴리스 = dev → main 릴리스 PR 하나로 정했고, 배포본은 main 뿐이다.

## 선택지
1. 작업 PR 을 쌓아 두고 사용자가 몰아서 병합 — 확인 횟수는 그대로, 의존 PR 이 쌓이면 rebase · 충돌 위험.
2. **작업 PR(→ dev)은 조건부로 Claude 가 병합, 사용자는 릴리스 PR(dev → main)에서 마일스톤 단위로 확인.**
3. PR 을 마일스톤 단위로 크게 — PR 수는 줄지만 diff 가 커서 리뷰가 어렵고 dev 이력이 흐려진다.

## 결정
2번(사용자 결정).
- Claude 가 dev 에 병합하는 조건: CI 전부 green · 리뷰 차단 0건 · 권고 "병합 권장" · **squash 만**. 하나라도 아니면 병합하지 않고 사용자에게 넘긴다.
- main 으로 가는 병합(릴리스 · hotfix · 역병합)과 PR 닫기는 계속 사용자만. 태그는 사용자 승인 후 Claude.
- 릴리스 PR 본문에 그 마일스톤의 PR 목록 · 각 리뷰 권고 · 남은 지적 · 수동 확인 항목을 모아, 그것만 읽고 판단할 수 있게 한다.

## 결과
- 강제: `guard-git.sh` 가 `gh pr merge` 를 `<번호> --squash [--delete-branch]` 형태이고 PR 의 base 가 dev 일 때만 통과시킨다(`gh pr view` 로 base 조회, 실패하면 차단). `--merge`·`--rebase`·`--admin`·`--auto`·메시지 지정은 차단. `settings.json` deny 에서 `gh pr merge` 를 빼고 allow 에 넣었다.
- dev 에 사람이 보기 전의 변경이 들어간다. 대신 CI · reviewer 서브에이전트 · 훅이 그 자리를 맡고, 릴리스 전에 되돌리는 PR 로 고칠 수 있다. main(배포본)은 여전히 사용자 확인 없이는 바뀌지 않는다.
- 이 ADR 을 들여온 PR(#6)은 Claude 자신의 권한을 넓히는 변경이므로 사용자가 병합한다.

## 개정 (2026-11-25)
사용자 결정: "dev > main 머지(release)말고는 알아서 진행해줘." v0.1.0 릴리스에서 hotfix 병합 · 역병합 병합 · 태그 승인 창 · A/B 선택을 매번 사용자에게 물은 것이 계기.
- 사용자 몫은 **릴리스 PR(dev → main) 병합 하나**로 줄인다.
- Claude 가 하는 것
  - 작업 PR squash
  - `hotfix/*` → main 병합 · 역병합(main → dev) 병합: merge commit
  - 태그 생성 · 푸시, `gh release create`, PR 닫기
- 계속 막는 것: 릴리스 PR 병합, `--rebase` · `--admin` · `--auto`, 강제 푸시, main · dev 직접 변경, `gh release delete`.
- 승인 창을 띄우는 것: 원격 태그 · ref 삭제, `--tags` 푸시.
- `guard-git.sh` 는 PR 의 head · base 를 조회해 병합 방법과 방향이 맞을 때만 통과시킨다.
- Claude 자신의 권한을 넓히는 변경이어서 auto 모드 분류기가 Claude 의 직접 수정을 막았다. 그래서 Claude 가 패치를 만들고, 사용자가 내용을 보고 적용했다.

## 개정 (#145, 2026-11-27) — 사용자 확인은 v1.0.0 이상 릴리스만

- 사용자 결정(2026-11-27): 주말 동안 쉬지 않고 진행하려고, v0.3.1 이후에는 **v1.0.0 미만 릴리스 PR 병합도 Claude 가 한다**. 사용자는 v1.0.0 이상의 main 병합만 확인한다.
- Claude 는 릴리스 PR 의 CI 가 green 이고 릴리스 리뷰 권고가 "릴리스 권장"일 때만 merge commit 으로 병합한다. 보류 권장이면 멈추고 보고한다.
- 사용자가 결과를 따라갈 수 있게 6시간마다(18 · 0 · 6 · 12시) 메일로 상황을 보고한다. 문제가 보이면 사용자는 언제든 멈추라고 하거나, 되돌리는 PR · hotfix 를 요청할 수 있다.
- `guard-git.sh` 는 릴리스 PR(dev → main)을 `--merge` 일 때 통과시킨다. 단 PR 제목의 버전(vX.Y.Z)이 1.0.0 이상이면 막는다. 이번 권한 확장은 사용자가 대화에서 직접 요청했다.
