# 0016. 여러 창 배치와 창 수명(ADR-0011 개정)

- 상태: 채택(#89, 2026-11-27)
- 날짜: 2026-11-27
- 관련: #87 · #88 · #89 · #176, FR-HIS-05 · FR-UI-03 · FR-LAY-04 · 07 · 10 · 12, ADR-0011(개정) · 0012

## 맥락
M3 까지 메인 창에는 터미널 창이 하나였다. `MainWindow` 가 `PaneController` 하나를 직접 들고, 끝난 창의 Esc 는 바로 앱을 끝냈다(ADR-0011). M4 에서 창이 여럿이 되면 다음을 정해야 한다.

1. 레이아웃 상태를 누가 가지는지.
2. 화면이 레이아웃을 어떻게 따라 그리는지.
3. 새 창의 셸을 언제 띄우는지.
4. 창 닫기 · 앱 닫기의 순서.

JediTerm 위젯은 다른 부모 컨테이너로 옮기면 `removeNotify` · `addNotify` 를 다시 겪는다. 크기도 두 번 바뀌어 셸에 resize 가 두 번 간다.

## 선택지
**레이아웃 상태**
- (a) UI(`MainWindow`)가 트리를 가진다. 키보드 · 마우스 · 트리 열기가 각자 UI 를 고치게 되고, 복원(M5)이 UI 를 거쳐야 한다.
- (b) **`StateActor` 의 `AppState.workspace` 가 가진다(ADR-0012).** UI 는 `LayoutChanged` 를 받아 그리기만 한다.

**배치 방식**
- (a) Split 마다 `JPanel` · `JSplitPane` 을 중첩한다. 분할할 때마다 기존 창이 새 부모로 옮겨진다.
- (b) **컨테이너 하나에 모든 창을 두고 위치만 계산한다.** domain `LayoutGeometry.rects` 가 계산한다. 창은 부모를 바꾸지 않는다.

## 결정
- 레이아웃 (b).
  - `Workspace`(트리 · 포커스 · 창별 명세 `PaneSpec`)는 `StateActor` 에서만 바뀐다.
  - 열기 · 닫기 · 포커스는 `OpenPaneUseCase` · `ClosePaneUseCase` · `FocusPaneUseCase` 로만 바꾼다(#88).
- 배치 (b).
  - `ui.layout.LayoutView` 의 `LayoutManager` 가 `LayoutGeometry.rects(tree, bounds, gap)` 로 각 창의 `setBounds` 를 정한다.
  - 경계선은 간격(6px)만 둔다. 드래그 · 키보드 크기 조정은 다음 이슈에서 같은 계산 위에 얹는다.
- 화면 갱신: `LayoutChanged` 를 받으면 순수 함수 `PaneDiff.between(이전, 다음)` 를 계산한다.
  - 사라진 창은 `shutdown()`(스트림 close)하고 뗀다.
  - 새 창은 붙인 뒤 **배치를 곧바로 확정(`validate`)하고 나서** 명세대로 셸을 띄운다. 첫 PTY 크기가 실제 창 크기가 된다.
  - 명세가 바뀐 창은 없애고 다시 만든다.
- 포커스
  - 창 안으로 키보드 포커스가 들어오면(클릭 · 이동) `FocusPaneUseCase` 를 부른다.
  - 강조 테두리는 지금처럼 키보드 포커스를 따른다(FR-UI-03).
  - 작업 공간의 포커스가 바뀌면 그 창으로 키보드 포커스를 옮긴다.
  - 탭 이름 · 상태줄 왼쪽은 포커스 창 기준이다. 창마다 마지막 글자를 기억해 두었다가 포커스가 바뀌면 바꿔 보인다.
- 창 닫기(ADR-0011 개정)
  - 끝난 창의 Esc 는 `ClosePaneUseCase` 를 부른다.
  - 창이 둘 이상이면 레이아웃이 줄고(`LayoutChanged`), 그 창의 세션은 트리에서 빠진다(`SessionsChanged`).
  - 마지막 창이면 `LastPaneClosed` 가 오고 앱을 끝낸다. 창이 하나일 때의 동작은 M2 와 같다.
- 앱 창 닫기(X): 실행 중 셸이 **2개 이상이면 확인**한다(M3 계획 U2). 취소하면 아무 일도 없다. 하나 이하면 지금처럼 바로 끝낸다.
- 앱 종료 순서: ADR-0011 #79 개정과 같다. 다만 1 · 4 단계가 "모든 창"이다 — 모든 창의 `shutdown()` 이 돌려준 종료 단계를 `allOf` 로 묶어 같은 기한 안에서 기다린다.

## 결과
- 좋아지는 점
  - 레이아웃이 바뀌는 길이 하나다(유스케이스 → 액터 → 이벤트 → 화면). 키보드 · 마우스 · 트리 열기 · 복원이 같은 길을 쓴다.
  - 분할해도 기존 터미널 위젯이 부모를 바꾸지 않는다.
  - 기하 계산이 순수 함수라 속성 테스트로 고정된다(영역 안 · 겹침 없음).
- 대가
  - 닫기 · 포커스가 액터를 한 번 거쳐 화면에 온다(비동기). 같은 틱 안에서 화면이 바로 바뀌지는 않는다.
  - 창이 생길 때 기존 창들의 크기가 바뀌어 각 셸에 resize 가 한 번 간다.

## 개정 (#176, 2026-11-28) — 여러 탭

- 작업 공간이 탭 목록을 가진다: `Workspace(tabs, active, specs, nextPane, nextTab)`. 탭은 `Tab(id, name, root, focused, zoomed)`.
  - 불변식: 탭 ≥ 1 · `0 ≤ active < tabs.size()` · 탭 ID 유일 · 탭들의 창 집합은 서로 겹치지 않고 그 합집합 = `specs` 의 키.
  - `tab()` 은 활성 탭이다. 창 연산(분할 · 크기 · 방향 포커스 · 줌 · 교환 · 끌어다 놓기)은 활성 탭에 적용한다. 그래서 탭 하나만 쓰는 호출부는 바뀌지 않는다.
  - 상태는 여전히 `StateActor` 의 `AppState.workspace` 하나가 가진다. 탭 연산도 순수 함수이고 새 값을 돌려준다.
- 순서
  - 새 탭(`newTab`)과 새 탭으로 옮기기(`movePaneToNewTab`)는 **맨 뒤**에 붙이고 활성화한다.
  - `moveTab(tab, toIndex)` 는 범위 밖 위치를 양 끝으로 고정한다. 활성 탭은 위치가 아니라 ID 로 따라간다.
  - `selectRelative` 는 양 끝에서 돈다. `selectIndex` 는 `active` · `moveTab` 처럼 0 부터 센다(Ctrl+1 → 0). 없는 번호면 `NoSuchIndex`.
- 마지막 탭
  - `closeTab` 으로 마지막 탭은 닫지 않는다(`TabError.LastTab`). 앱을 끝내는 길은 마지막 창 닫기(`LayoutError.LastPane` → `LastPaneClosed`) 하나로 둔다.
  - 탭을 닫으면 그 탭 창들의 명세도 지운다. 활성 탭이었으면 오른쪽 이웃, 없으면 왼쪽 이웃이 활성이 된다.
- 탭의 마지막 창(FR-LAY-04)
  - `close(pane)` 은 창이 든 탭을 찾는다. 활성 탭이 아니어도 된다.
  - 그 탭에 창이 둘 이상이면 지금처럼 트리에서 뺀다. 유일한 창이고 다른 탭이 있으면 탭을 닫는다. 모든 탭을 통틀어 마지막 창이면 `LastPane` 이다.
  - `movePaneToTab` 으로 탭의 유일한 창을 옮기면 빈 탭은 닫힌다(탭은 창 없이 있을 수 없다). `movePaneToNewTab` 은 유일한 창이면 `SolePane` 이다 — 옮겨도 달라지는 게 없다.
- 포커스와 줌
  - `focus(pane)` 이 다른 탭의 창이면 그 탭을 활성화한다(사이드바 세션 포커스).
  - 줌 규칙(#147)은 탭마다 따로다. 탭을 바꿔도 각 탭의 포커스 · 줌은 그대로다. 창을 옮기면 원래 탭과 대상 탭 모두 레이아웃이 바뀌어 줌이 풀린다.
- 번호 규칙
  - 창 `p<n>` 과 탭 `t<n>` 의 번호는 늘기만 한다. 닫은 번호를 다시 쓰지 않는다(창 번호와 같은 까닭 — 늦게 온 이전 탭의 이벤트가 새 탭에 붙지 않게).
  - 생성자가 `nextPane` > 모든 `p<n>`, `nextTab` > 모든 `t<n>` 를 검사한다. 복원(M5)이 저장된 번호를 그대로 읽어도 새 번호가 겹치지 않는다. 번호 꼴이 아닌 ID 는 이 규칙과 상관없다.
- 탭 이름: `TabName` — 앞뒤 공백을 떼고 1~40 코드 포인트, 제어 문자 없음. 이름이 비면 화면은 포커스 창 제목을 쓴다(자동 이름, 지금과 같다).
- 탭 하나짜리 생성자 `new Workspace(Tab, specs, nextPane)` 는 지우고 팩터리 `Workspace.single(Tab, specs, nextPane)` 를 둔다.
- 화면(탭 줄 · 탭별 창 보이기)과 유스케이스 · 저장은 이 개정의 범위 밖이다. 이 개정 시점의 `PaneDiff` 와 `MainWindow` 는 활성 탭의 창만 본다.
