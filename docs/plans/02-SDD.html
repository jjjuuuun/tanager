1.1 목적

Tanager 가 무엇을 하고(요구사항) 어떻게 동작하도록 설계했는지(구조·모델·동작·인터페이스·데이터)를 한곳에 정리한다. 구현자(사람과 에이전트)가 이 문서와 ADR 만 보고 같은 판단을 내릴 수 있는 것이 목표다.

1.2 범위

  • 포함: Windows 11 (WSL2 · Windows PowerShell 5.1 · cmd) 용 v1.0, macOS 확장을 위한 설계 지점
  • 제외: PowerShell 7(pwsh) 등 그 밖의 셸과 사용자 정의 프로파일, 원격 SSH 세션 관리, 셸 프로세스 자체의 상태 복원(스크롤백·실행 중 프로그램), AI 도구 설정 편집

1.3 문서 구성

IEEE 1016 의 설계 관점(컨텍스트 · 구성 · 논리 · 상호작용 · 상태 · 인터페이스 · 정보 · 배치)을 따르되, 이 프로젝트에 맞게 줄였다. 요구사항 ID(FR-…, NFR-…)는 이슈 템플릿의 "SDD 요구사항 ID" 칸과 §13 추적표에서 쓴다.

2.제품 개요

2.1 해결하려는 문제

잊어버리는 작업 경로

WSL 에서 Claude Code 등으로 여러 프로젝트를 오가다 컴퓨터를 껐다 켜면, 어느 디렉터리에서 무엇을 하고 있었는지 알 수 없다.

흩어진 터미널

WSL 과 PowerShell 을 서로 다른 창·앱에서 쓰고, 분할·크기 조절은 tmux(WSL 전용)나 Windows Terminal 에 따로 의존한다.

경로마다 다른 도구

프로젝트마다 쓸 수 있는 Claude Code 스킬·서브에이전트·MCP 가 다른데, 확인하려면 여러 숨김 폴더와 JSON 을 열어 봐야 한다.

두 세계의 경로

같은 폴더가 WSL 에서는 /mnt/c/…, Windows 에서는 C:\… 라서 이력이 둘로 나뉜다.

2.2 제품 목표

  1. 셸이 이동한 모든 작업 경로를 자동으로 기록하고, 환경별 폴더 트리로 보여 준다. 폴더 아래에는 그 폴더에서 실행 중인 세션이 매달린다.
  2. 한 창 안에서 WSL · PowerShell · cmd 세션을 tmux 처럼 분할·크기 조절·포커스 이동한다.
  3. 재부팅 후 다시 열면 탭·분할·각 창의 셸과 마지막 경로가 그대로 돌아온다.
  4. 폴더나 세션을 고르면 그 경로에서 쓸 수 있는 AI 도구 구성(스킬·에이전트·메모리·MCP·훅·권한)을 프로젝트용/전체 공통으로 나눠 보여 준다.
  5. OS 의존 부분을 격리해 macOS 를 모듈 추가만으로 지원한다.

2.4 대표 시나리오

  1. 아침에 다시 켜기Tanager 를 열면 어제의 탭 2개와 분할 3개가 그대로 생기고, 각 창이 어제 마지막 경로에서 bash · PowerShell 로 뜬다. 사라진 경로는 홈에서 뜨고 알림이 나온다.
  2. 예전 프로젝트 찾기트리에서 WSL · Ubuntu › /home/me › proj › api 를 찾아 더블클릭 → 현재 창 오른쪽에 그 경로의 새 창이 열린다. 검색창에 "api" 를 쳐도 된다.
  3. 이 프로젝트에서 뭘 쓸 수 있지?Tanager 폴더를 클릭 → 도구함에 이 프로젝트의 스킬 tdd · commit · pr · adr 와 전체 공통 스킬, MCP 2개가 보인다. tdd 의 "터미널에 입력"을 누르면 claude 가 도는 창에 /tdd 가 들어간다.
  4. 같은 폴더를 PowerShell 로WSL 폴더 /mnt/c/work/infra 우클릭 → "PowerShell 로 열기" → C:\work\infra 에서 PowerShell 창이 열린다.

2.5 하지 않는 것

  • 셸 명령·출력 내용 저장(경로만 기록)
  • AI 도구 설정 편집(읽기 전용, 파일 열기만 제공)
  • 원격 호스트(SSH) 세션 관리 — 이후 검토
  • PowerShell 7 · 사용자 정의 프로파일 — Windows 기본 구성 요소인 PowerShell 5.1 과 cmd, WSL 만 지원(사용자 결정)

4.아키텍처

4.1 구성 요소

모듈과 의존 규칙은 계획서 1 §3, 결정 근거는 ADR-0002. 요약하면:

  • domain — 순수 규칙. I/O · 스레드 · 시간 없음(시간은 인자로 받음).
  • application — 유스케이스가 포트를 호출하고 도메인 함수를 적용한다. 모든 상태 변경은 StateActor(단일 스레드 실행기)에서 직렬화된다.
  • 어댑터 — 포트 구현. 서로 모른다. UI 는 TerminalStream 을 JediTerm TtyConnector 로 감싸므로 pty4j 를 모른다.
  • app/bootstrap — 객체 조립, ServiceLoader 로 현재 OS 의 PlatformModule 과 모든 ToolkitProvider 를 찾는다.

public sealed interface ShellEnvironment {

/** 불변식: 절대 경로, 정규화됨(중복 구분자·'.'·'..' 없음, 루트 외 끝 구분자 없음).

    public static Result<WorkspacePath, PathError> parse(ShellEnvironment env, String raw) { ... }
    public Key key() { ... }                 // 비교·맵 키: Windows 는 소문자화
    public List<String> segments() { ... }
    public Optional<WorkspacePath> parent() { ... }
}

                               int visitCount, boolean pinned, Optional<String> alias, boolean hidden) {}

public record WorkHistory(Map<WorkspacePath.Key, VisitedDirectory> entries, HistoryPolicy policy) {
    public Changed<WorkHistory> recordVisit(WorkspacePath path, Instant at) { ... }
    public Result<Changed<WorkHistory>, HistoryError> pin(WorkspacePath path, boolean pinned) { ... }
    public Result<Changed<WorkHistory>, HistoryError> alias(WorkspacePath path, Optional<String> alias) { ... }
    public Result<Changed<WorkHistory>, HistoryError> forget(WorkspacePath path) { ... }
}

/** 순수 투영: 이력 + 실행 중 세션 → 사이드바 트리 */
public final class DirectoryTree {
    public static List<TreeNode> project(WorkHistory h, Map<PaneId, LiveSession> live, TreeOptions o) { ... }
}

불변식: 같은 Key 는 하나 · visitCount ≥ 1 · firstVisited ≤ lastVisited · 항목 수 ≤ 한도(고정 항목 제외 오래된 순 제거) · 제외 규칙에 맞는 경로는 기록되지 않음.

트리 규칙: 루트 = 고정됨, 환경(정렬: WSL 배포판 → Windows). 경로 세그먼트로 트리를 만들고, 방문하지 않은 중간 노드가 자식 하나뿐이면 압축. 실행 중 세션은 cwd 가 같은 폴더 노드의 자식으로 붙인다(방문 기록이 없는 경로라도 세션이 있으면 노드를 만든다).

6.동작 설계

6.1 cwd 추적

  • 스캐너는 상태 기계다: ESC ] 7 ; 또는 ESC ] 9 ; 9 ; 로 시작해 BEL 또는 ESC \ 로 끝나는 시퀀스를 read 경계를 넘어 모은다. 최대 길이(4KB)를 넘으면 버린다.
  • OSC 7 은 file://host/퍼센트인코딩경로 → UTF-8 디코딩. OSC 9;9 는 따옴표 안의 Windows 경로.
  • 같은 경로가 연속으로 오면 무시(프롬프트마다 오므로). 다른 경로일 때만 recordVisit.

6.2 시작과 복원

  1. 플랫폼 선택 → 셸 통합 스크립트를 앱 데이터에 설치(버전이 같으면 건너뜀).
  2. state.json 읽기 → schemaVersion 이 낮으면 마이그레이션 체인 적용 → 실패하면 .bak → 그래도 실패하면 빈 작업 공간 + 알림.
  3. 프로파일이 사라졌으면(예: 배포판 삭제) 기본 프로파일로, 경로가 없으면 홈으로 바꾸고 창 머리줄에 알림.
  4. UI 에 레이아웃을 먼저 그리고, 세션은 창마다 병렬로 띄운다(시작 시간 NFR-02).

6.4 저장

StateActor 가 상태를 바꿀 때마다 "저장 예약"을 갱신하고, 마지막 변경 후 1초가 지나면 I/O 스레드가 스냅샷을 직렬화해 state.json.tmp 에 쓰고 ATOMIC_MOVE 로 교체한다. 교체 전에 기존 파일을 state.json.bak 으로 남긴다. 앱 종료 시에는 즉시 저장한다.

6.5 마우스 레이아웃 조작

  • UI 는 판정만 도메인에 묻는다: 경계선 위치 = LayoutGeometry.dividers, 놓을 곳 = dropZone, 드래그 비율 = ratioAt. 마우스 좌표 계산 로직을 Swing 코드에 두지 않으므로 단위 테스트가 된다.
  • 드래그 중에는 UI 가 미리보기(반투명 오버레이 · 임시 경계선)만 그린다. 놓는 순간 ResizePaneUseCase.resizeTo / MovePaneUseCase 를 한 번 부르고, StateActor 가 새 트리를 발행하면 그때 셸 크기(TerminalStream.resize)를 바꾼다 — 드래그 중 셸에 수십 번 SIGWINCH 를 보내지 않는다.
  • 경계선은 JSplitPane 기본 디바이더 대신 얇은 둥근 핸들을 직접 그린다(FR-UI-03). 마우스를 올리면 150ms 동안 강조색으로 서서히 바뀐다.
  • 터미널 본문의 마우스 입력은 셸 앱(vim, htop 등의 마우스 모드)에 그대로 넘긴다. 레이아웃 조작은 머리줄 · 경계선 · 드롭 오버레이에서만 받으므로 충돌하지 않는다.
  • 모든 마우스 조작은 키보드 바인딩과 같은 유스케이스를 부른다. 그래서 동작 차이가 생기지 않고, 테스트는 유스케이스 수준에서 한 번만 쓴다.

6.6 리소스 수집

  1. WatchResourcesUseCase 가 가상 스레드 하나에서 주기(기본 2초)마다 PlatformModule.resources() 를 부른다. 결과는 저장 상태가 아니므로 StateActor 를 거치지 않고 ResourceSampled 이벤트로 바로 UiDispatcher 에 보낸다.
  2. 호스트 CPU · 메모리: com.sun.management.OperatingSystemMXBean(getCpuLoad · getTotalMemorySize · getFreeMemorySize). JDK 만으로 Windows · macOS 모두 된다 ✱(Windows 에서 값이 작업 관리자와 맞는지 M5 구현 때 확인).
  3. 디스크: 포커스 창 cwd 의 루트(C:\ 등)에 대해 FileStore.getTotalSpace / getUsableSpace.
  4. WSL: 실행 중인 WSL 세션이 있을 때만, 그 배포판에 wsl.exe -d <배포판> -- sh -c 'cat /proc/meminfo; df -kP /' 를 5초 이상 간격으로 실행해 파싱(MeminfoParser · DfParser 는 픽스처로 테스트하는 순수 함수).
  5. 판정: CpuWindow.level · Usage.ratio 와 Thresholds 비교 → 상태줄 항목 색. 상태줄에서 항목을 끄면 그 수집도 멈춘다.

6.7 테마 적용

  1. 시작 시 ThemeResolver.resolve(설정 모드, SystemAppearance)(순수 함수) → LIGHT 또는 DARK. 설정이 SYSTEM 이면 OS 값을 쓴다.
  2. PlatformModule.appearance() 가 OS 변경을 구독한다. Windows: 레지스트리 HKCU\…\Themes\Personalize\AppsUseLightTheme 변경 감지 ✱, '애니메이션 효과' 설정 · macOS: NSApp.effectiveAppearance ✱.
  3. 바뀌면 AppearanceChanged → EDT 에서 FlatLaf 테마 교체(FlatAnimatedLafChange 로 200ms 페이드) + 모든 JediTerm 위젯의 색 팔레트 교체. 셸은 재시작하지 않는다.

[ -f ~/.bashrc ] && . ~/.bashrc

__tanager_osc7() {
  local LC_ALL=C p=$PWD out= c i
  for (( i = 0; i < ${#p}; i++ )); do            # 바이트 단위 퍼센트 인코딩 (한글 경로 대응)
    c=${p:i:1}            # LC_ALL=C 덕분에 바이트 단위 — 빼면 한글이 %D55C 처럼 깨진다(M0 에서 재현)
    case $c in
      [a-zA-Z0-9/._~-]) out+=$c ;;
      *) printf -v c '%%%02X' "'$c"; out+=$c ;;
    esac
  done
  printf '\e]7;file://%s%s\e\\' "$HOSTNAME" "$out"
}
PROMPT_COMMAND="__tanager_osc7${PROMPT_COMMAND:+;$PROMPT_COMMAND}"

# 프로필($PROFILE)은 이미 로드된 뒤. 기존 prompt 를 감싸서 앞에 OSC 9;9 를 붙인다 (oh-my-posh 등과 공존)
$global:__TanagerPrompt = $function:prompt
function global:prompt {
    $loc = $executionContext.SessionState.Path.CurrentLocation
    $out = & $global:__TanagerPrompt
    if ($loc.Provider.Name -eq 'FileSystem') {
        $e = [char]27
        return "$e]9;9;`"$($loc.ProviderPath)`"$e\" + $out
    }
    return $out
}

  • 프리릴리스 태그(vX.Y.Z-rc.N)에는 MSI 를 붙이지 않는다. MSI 버전은 숫자(X.Y.Z)뿐이라 rc 와 정식의 ProductCode 가 같아져, 정식판을 rc 위에 설치하면 업그레이드가 안 된다(zip 만 배포).
  • 런타임 모듈: 빌드 때 computeRuntimeModules 가 jdeps --print-module-deps 로 계산하고 정적 분석으로 안 잡히는 jdk.charsets · jdk.accessibility 를 더한다(목록은 build/jpackage/runtime-modules.txt). M1 기준 java.base · java.desktop · java.sql · jdk.accessibility · jdk.charsets(+의존 모듈). 터미널(pty4j · JNA)이 실제로 도는 M2 에서 app-image 로 다시 확인 ✱.
  • 시작 시간: AppCDS 아카이브를 빌드 시 생성해 포함.
  • pty4j 네이티브 라이브러리는 jar 에서 풀려 사용자 디렉터리에 캐시된다 — 설치 경로가 읽기 전용이어도 동작한다(M0: pty4j 0.14 가 번들 conpty.dll 을 %TEMP% 에 풀어 씀). Java 25 의 JNA restricted method 경고 → 실행 옵션 --enable-native-access=ALL-UNNAMED.
  • app-image 크기: M0 전체 런타임 132MB → M1 모듈 축소 후 92MB.
  • MSI(#22): 업그레이드 UUID a8147190-fd5c-4984-942c-8d2d135c8af2 고정(바꾸면 이전 버전 위에 업그레이드 설치가 안 된다). 버전은 태그의 숫자 부분(-rc.1 같은 꼬리는 MSI 버전 규칙상 빠진다), 제조사 Tanager. 설치 화면은 없다 — MIT 는 동의가 필요 없으므로 --license-file 대신 LICENSE.txt 를 설치 폴더에 넣는다(고지 · D2Coding OFL 과 함께 이미지 루트). WiX 가 PATH 에 없으면 태스크가 설치 방법을 알리며 실패한다.
  • NFR-09 확인(#22, Windows 11, 일반 사용자 · Medium 무결성): CI MSI(약 38MB)를 msiexec /i … /qn 로 관리자 권한 요청 없이 설치(로그 MSI_LUA: … no elevation required, 설치 폴더 약 96MB) → 시작 메뉴 바로 가기로 실행(자식 프로세스 창 "Tanager", WSL bash 프롬프트) → msiexec /x … /qn 로 설치 폴더 · 시작 메뉴 · 제거 항목이 남지 않음.
  • 터미널 기본 글꼴 D2Coding(SIL OFL 1.1)을 앱에 번들한다(FR-UI-06, ADR-0001).
  • 제3자 고지(#67): 번들되는 제3자 jar 마다 라이선스 전문과 NOTICE 를 저장소 루트 licenses/ 에 두고, 빌드가 이미지 루트의 licenses/(D2Coding OFL 과 같은 폴더)로 넣는다. 어느 구성 요소가 어느 파일을 따르는지는 THIRD-PARTY-NOTICES.md 표에 있고, 이중 라이선스(JediTerm · JNA)는 Apache-2.0 을 고른다. Java 런타임은 jlink 가 넣는 runtime/legal/ 을 가리킨다. verifyAppImage 가 문서에 적힌 파일 · jar 와 이미지를 양쪽으로 대조하고 runtime/legal/ 이 있는지 검사한다 — 의존성을 바꾸면 고지도 같은 PR 에서 고친다.
  • 코드 서명이 없으면 SmartScreen 경고가 뜬다 → v1.0 전에 서명 여부 결정(리스크 R6).
