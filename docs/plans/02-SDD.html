1.1 목적

Tanager 가 무엇을 하고(요구사항) 어떻게 동작하도록 설계했는지(구조·모델·동작·인터페이스·데이터)를 한곳에 정리한다. 구현자(사람과 에이전트)가 이 문서와 ADR 만 보고 같은 판단을 내릴 수 있는 것이 목표다.

1.2 범위

  • 포함: Windows 11 (WSL2 · Windows PowerShell 5.1 · cmd) 용 v1.0, macOS 확장을 위한 설계 지점
  • 제외: PowerShell 7(pwsh) 등 그 밖의 셸과 사용자 정의 프로파일, 원격 SSH 세션 관리, 셸 프로세스 자체의 상태 복원(스크롤백·실행 중 프로그램), AI 도구 설정 편집

1.3 문서 구성

IEEE 1016 의 설계 관점(컨텍스트 · 구성 · 논리 · 상호작용 · 상태 · 인터페이스 · 정보 · 배치)을 따르되, 이 프로젝트에 맞게 줄였다. 요구사항 ID(FR-…, NFR-…)는 이슈 템플릿의 "SDD 요구사항 ID" 칸과 §13 추적표에서 쓴다.

2.제품 개요

2.1 해결하려는 문제

잊어버리는 작업 경로

WSL 에서 Claude Code 등으로 여러 프로젝트를 오가다 컴퓨터를 껐다 켜면, 어느 디렉터리에서 무엇을 하고 있었는지 알 수 없다.

흩어진 터미널

WSL 과 PowerShell 을 서로 다른 창·앱에서 쓰고, 분할·크기 조절은 tmux(WSL 전용)나 Windows Terminal 에 따로 의존한다.

경로마다 다른 도구

프로젝트마다 쓸 수 있는 Claude Code 스킬·서브에이전트·MCP 가 다른데, 확인하려면 여러 숨김 폴더와 JSON 을 열어 봐야 한다.

두 세계의 경로

같은 폴더가 WSL 에서는 /mnt/c/…, Windows 에서는 C:\… 라서 이력이 둘로 나뉜다.

2.2 제품 목표

  1. 셸이 이동한 모든 작업 경로를 자동으로 기록하고, 환경별 폴더 트리로 보여 준다. 폴더 아래에는 그 폴더에서 실행 중인 세션이 매달린다.
  2. 한 창 안에서 WSL · PowerShell · cmd 세션을 tmux 처럼 분할·크기 조절·포커스 이동한다.
  3. 재부팅 후 다시 열면 탭·분할·각 창의 셸과 마지막 경로가 그대로 돌아온다.
  4. 폴더나 세션을 고르면 그 경로에서 쓸 수 있는 AI 도구 구성(스킬·에이전트·메모리·MCP·훅·권한)을 프로젝트용/전체 공통으로 나눠 보여 준다.
  5. OS 의존 부분을 격리해 macOS 를 모듈 추가만으로 지원한다.

2.4 대표 시나리오

  1. 아침에 다시 켜기Tanager 를 열면 어제의 탭 2개와 분할 3개가 그대로 생기고, 각 창이 어제 마지막 경로에서 bash · PowerShell 로 뜬다. 사라진 경로는 홈에서 뜨고 알림이 나온다.
  2. 예전 프로젝트 찾기트리에서 WSL · Ubuntu › /home/me › proj › api 를 찾아 더블클릭 → 현재 창 오른쪽에 그 경로의 새 창이 열린다. 검색창에 "api" 를 쳐도 된다.
  3. 이 프로젝트에서 뭘 쓸 수 있지?Tanager 폴더를 클릭 → 도구함에 이 프로젝트의 스킬 tdd · commit · pr · adr 와 전체 공통 스킬, MCP 2개가 보인다. tdd 의 "터미널에 입력"을 누르면 claude 가 도는 창에 /tdd 가 들어간다.
  4. 같은 폴더를 PowerShell 로WSL 폴더 /mnt/c/work/infra 우클릭 → "PowerShell 로 열기" → C:\work\infra 에서 PowerShell 창이 열린다.

2.5 하지 않는 것

  • 셸 명령·출력 내용 저장(경로만 기록)
  • AI 도구 설정 편집(읽기 전용, 파일 열기만 제공)
  • 원격 호스트(SSH) 세션 관리 — 이후 검토
  • PowerShell 7 · 사용자 정의 프로파일 — Windows 기본 구성 요소인 PowerShell 5.1 과 cmd, WSL 만 지원(사용자 결정)

불변식: 같은 경로(환경별 비교)는 하나 · visitCount ≥ 1 · firstVisited ≤ lastVisited · recordVisit · restore 직후 항목 수 ≤ max(한도, 고정 수 + 1)(고정 · 방금 방문한 항목은 남기고 오래된 순 제거, ADR-0012) · withPolicy 직후 항목 수 ≤ max(한도, 고정 수) · 제외 규칙에 맞는 경로는 기록되지 않음(고정 항목은 규칙에 맞아도 남김).

가져오기(importVisits, #207): 제외 경로 · 배치와 다른 환경의 경로는 건너뛰고, 배치 안의 같은 경로는 기간을 합쳐 하나로 본다. 있는 항목은 출처만 더하고 first = min · last = max(방문 횟수 · 고정 · 별칭 · 숨김은 그대로). 없는 항목은 lastSeen 이 워터마크 importedUntil(origin) 보다 늦을 때만 만든다(횟수 1, 워터마크가 없으면 모두) — 사용자가 지운 경로는 그 뒤에 새 대화가 생길 때만 돌아온다. 워터마크는 max(이전, scannedAt, 배치의 가장 늦은 lastSeen) 으로 줄지 않는다. 한도 정리는 withPolicy 와 같다. 같은 배치를 두 번 적용해도 결과가 같다(속성 테스트).

트리 규칙: 루트 = 고정됨, 환경(정렬: WSL 배포판 → Windows). 경로 세그먼트로 트리를 만들고, 방문하지 않은 중간 노드가 자식 하나뿐이면 압축. 실행 중 세션은 cwd 가 같은 폴더 노드의 자식으로 붙인다(방문 기록이 없는 경로라도 세션이 있으면 노드를 만든다).

StateActor 가 명령을 적용한 뒤 바뀐 스냅샷을 이벤트로 발행하고, UI 는 AppEvents.subscribeOnUi(UiDispatcher 경유)로 EDT 에서 받는다. 저장 상태가 아닌 리소스 표본 · 테마(ApplyThemeUseCase, ADR-0018)는 StateActor 를 거치지 않는다(§6).

6.동작 설계

6.1 cwd 추적

  • 스캐너는 상태 기계다: ESC ] 7 ; 또는 ESC ] 9 ; 9 ; 로 시작해 BEL 또는 ESC \ 로 끝나는 시퀀스를 read 경계를 넘어 모은다. 최대 길이(4KB)를 넘으면 버린다.
  • OSC 7 은 file://host/퍼센트인코딩경로 → UTF-8 디코딩. OSC 9;9 는 따옴표 안의 Windows 경로.
  • 같은 경로가 연속으로 오면 무시(프롬프트마다 오므로). 다른 경로일 때만 recordVisit.

6.2 시작과 복원

  1. 플랫폼 선택 → 셸 통합 스크립트를 앱 데이터에 설치(버전이 같으면 건너뜀).
  2. state.json 읽기 → schemaVersion 이 낮으면 마이그레이션 체인 적용 → 실패하면 .bak → 그래도 실패하면 빈 작업 공간 + 알림.
  3. 프로파일이 사라졌으면(예: 배포판 삭제) 그 창에 셸 선택 화면(FR-SES-02)을 띄우고, 경로가 없으면 홈으로 바꾸고 창 머리줄에 알림. 복원(M5) 설계 때 다시 확인한다.
  4. UI 에 레이아웃을 먼저 그리고, 세션은 창마다 병렬로 띄운다(시작 시간 NFR-02).

6.3 세션 상태

6.4 저장

StateActor 가 상태를 바꾸면 "저장 예약"을 건다. 첫 미저장 변경 후 1초 안에 I/O 스레드가 스냅샷을 직렬화해 state.json.tmp 에 쓰고 ATOMIC_MOVE 로 교체한다. 변경이 계속 와도 1초마다 한 번은 쓴다(throttle — 트레일링 디바운스는 저장이 계속 밀린다). 저장은 한 번에 하나만 돈다. 앱 종료 시에는 즉시 저장한다(저장 시점은 #79, ADR-0013).

state.json.bak 은 실행마다 첫 저장 직전에 한 번 그때의 state.json 을 복사해 만든다. 교체 때마다 갱신하면 같은 실행 안의 논리 오류로 망가진 이력이 1초 뒤 백업까지 덮는다. 기존 파일이 없거나 불러올 때 손상으로 판정한 파일이면 만들지 않는다(ADR-0013).

6.5 마우스 레이아웃 조작

  • UI 는 판정만 도메인에 묻는다: 경계선 위치 = LayoutGeometry.dividers, 놓을 곳 = dropZone, 드래그 비율 = ratioAt. 마우스 좌표 계산 로직을 Swing 코드에 두지 않으므로 단위 테스트가 된다.
  • 드래그 중에는 UI 가 미리보기(반투명 오버레이 · 임시 경계선)만 그린다. 놓는 순간 ResizePaneUseCase.resizeTo / MovePaneUseCase 를 한 번 부르고, StateActor 가 새 트리를 발행하면 그때 셸 크기(TerminalStream.resize)를 바꾼다 — 드래그 중 셸에 수십 번 SIGWINCH 를 보내지 않는다.
  • 경계선은 JSplitPane 기본 디바이더 대신 얇은 둥근 핸들을 직접 그린다(FR-UI-03). 마우스를 올리면 150ms 동안 강조색으로 서서히 바뀐다.
  • 터미널 본문의 마우스 입력은 셸 앱(vim, htop 등의 마우스 모드)에 그대로 넘긴다. 레이아웃 조작은 머리줄 · 경계선 · 드롭 오버레이에서만 받으므로 충돌하지 않는다.
  • 모든 마우스 조작은 키보드 바인딩과 같은 유스케이스를 부른다. 그래서 동작 차이가 생기지 않고, 테스트는 유스케이스 수준에서 한 번만 쓴다.

6.6 리소스 수집

  1. WatchResourcesUseCase 가 가상 스레드 하나에서 주기(기본 2초)마다 PlatformModule.resources() 를 부른다. 결과는 저장 상태가 아니므로 StateActor 를 거치지 않고 ResourceSampled 이벤트로 바로 UiDispatcher 에 보낸다.
  2. 호스트 CPU · 메모리: com.sun.management.OperatingSystemMXBean(getCpuLoad · getTotalMemorySize · getFreeMemorySize). JDK 만으로 Windows · macOS 모두 된다 ✱(Windows 에서 값이 작업 관리자와 맞는지 M5 구현 때 확인).
  3. 디스크: 포커스 창 cwd 의 루트(C:\ 등)에 대해 FileStore.getTotalSpace / getUsableSpace.
  4. WSL: 실행 중인 WSL 세션이 있을 때만, 그 배포판에 wsl.exe -d <배포판> --exec sh -c "cat /proc/meminfo; LC_ALL=C df -kP /"(로그인 셸을 거치지 않게 --exec, 환경 WSL_UTF8=1, 시간 초과 1초 — #187) 를 5초 이상 간격으로 실행해 파싱(MeminfoParser · DfParser 는 픽스처로 테스트하는 순수 함수).
  5. 판정: CpuWindow.level · Usage.ratio 와 Thresholds 비교 → 상태줄 항목 색. 상태줄에서 항목을 끄면 그 수집도 멈춘다.

6.7 테마 적용

  1. 시작 시 ThemeResolver.resolve(설정 모드, SystemAppearance)(순수 함수) → LIGHT 또는 DARK. 설정이 SYSTEM 이면 OS 값을 쓰고, OS 값을 읽지 못하면 DARK. 움직임도 같다(AUTO 는 OS 값, ON · OFF 는 강제).
  2. PlatformModule.appearance() 는 지금 값만 읽는다(SystemAppearance(Optional<Theme>, animations)). Windows: reg.exe query 로 HKCU\…\Themes\Personalize\AppsUseLightTheme(0x0 = 다크) · '애니메이션 효과'(MinAnimate) · macOS: NSApp.effectiveAppearance ✱(M7). 변경 감지는 application 의 AppearanceWatcher 가 구독이 있는 동안 5초마다, 그리고 창 활성화 때 다시 읽어 한다 — 네이티브 변경 알림을 쓰지 않는다(ADR-0018).
  3. 설정과 합친 값이 바뀌면 ApplyThemeUseCase 구독자에게 EDT 에서 알린다 → EDT 에서 FlatLaf 테마 교체(FlatAnimatedLafChange 로 200ms 페이드) + 모든 JediTerm 위젯의 색 팔레트 교체. 셸은 재시작하지 않는다.

7.3 Claude Code 작업 이력 가져오기 (FR-TK-09)

Claude Code 는 사용한 디렉터리별로 ~/.claude/projects/<인코딩된 경로>/<세션ID>.jsonl 에 대화 기록을 남긴다. 디렉터리 이름 인코딩은 되돌릴 수 없으므로(/·. → -) 각 기록 파일에서 다음 세 가지만 읽는다. 형식이 공개 사양이 아니므로 실패하면 기능을 끄고 경고만 남긴다.

  • 작업 경로(cwd): 이력에 "Claude 사용" 표시와 함께 넣는다.
  • 첫 사용자 메시지의 앞부분(최대 80자): 대화 목록의 요약 글자. 그 밖의 대화 내용은 읽지 않고, 요약도 저장하지 않는다(목록을 그릴 때만 메모리에 둔다).
  • 파일의 마지막 수정 시각: 목록의 순서(최근 먼저)와 날짜.

M0 확인 결과: 디렉터리 이름은 되돌릴 수 없다(한글 경로 → -----). 각 *.jsonl 의 여러 종류 줄에 cwd 필드가 있으므로, 파일마다 cwd 가 있는 첫 줄과 첫 사용자 메시지 줄까지만 읽는다. cwd 를 못 찾은 파일은 건너뛴다.

포트(#208, ADR-0020): application 의 출력 포트 ConversationSource(SPI, ServiceLoader 로 여럿) — scan(env, hostHome) 이 Result<ConversationScan, ConversationError>(NoHistory · UnknownFormat · Unreadable → 그 환경의 기능을 끈다)를, resume(id) · continueLatest() 가 셸에 입력할 한 줄(ShellLine, Enter 없음)을 준다. Claude 구현은 app/adapter/toolkit/claude 의 ClaudeProjectsImporter 다. 파일마다 앞 200줄 또는 256KB 까지만 읽고, 대화는 도메인 PastConversation(출처 · ConversationId · cwd · 요약 · 수정 시각)으로 메모리에만 둔다.

트리 모양(사용자 결정 2026-11-27): Claude 를 쓴 폴더 아래에 실행 중 세션과 함께 이전 대화(💬 요약 · 날짜)를 최근 순으로 둔다. 대화를 더블클릭하거나 메뉴 "이어서 하기"를 고르면 그 폴더에서 같은 환경의 기본 셸로 새 창을 열고 claude --resume <세션ID> 를 입력 · 실행한다. 폴더 메뉴에는 "여기서 claude --continue"(마지막 대화)도 둔다.

8.2 키 바인딩 (기본값, Windows)

macOS 에서는 Ctrl 자리가 Cmd 로 바뀐다(PlatformModule.defaultKeymap()). prefix 모드는 기본 꺼짐이며 keys.prefix(예 "ctrl B")를 적으면 켜진다(M6, #193). prefix 를 누르면 1.5초 동안 다음 키 하나를 아래 prefix 열로 해석하고 상태줄에 PREFIX 를 보인다. 화살표 · Ctrl+화살표는 누른 키로, % · " · { 같은 글자 키는 자판마다 키 코드가 달라 그 키가 만든 글자로 판정한다. 열에 없는 키 · Esc · 시간 초과는 취소이고 그 키는 셸로 가지 않는다(시간 초과 뒤에 누른 키는 간다). prefix 를 두 번 누르면 두 번째는 그대로 셸로 간다(tmux 관례, Ctrl+B → 0x02). prefix 키는 재정의와 같은 예약 키 규칙을 따르고 기본 · 재정의 키와 겹치면 알리고 prefix 모드를 끈다. 탭 · 명령 팔레트 열(c n p 0…9 · :)은 그 기능(#181 등)이 들어올 때 더한다.

v1(v0.3 · v0.4)과 다른 점(#178): 탭 title → name(null = 자동 이름), 창의 lastCwd 는 문자열이 아니라 이력 항목과 같은 {env, path}(프로파일이 사라져도 경로의 환경을 안다), nextPane · nextTab 은 저장하지 않고 읽을 때 계산한다. v0.3 · v0.4 는 v2 파일을 읽기 전용으로 연다.

읽기 · 쓰기 규칙(ADR-0013, #78 · #178 — JsonStateRepository 가 HistoryRepository · WorkspaceRepository 를 함께 구현):

  • 항목: env.kind 는 wsl(+ distro) 또는 windows. 시각은 ISO-8601 UTC(Instant.toString). alias 가 없으면 null. sources 는 출처(VisitSource, [a-z0-9][a-z0-9-]{0,31}) 집합으로 읽고 id 순으로 쓴다(#207). 모르는 출처(다음 버전이 쓴 값)도 형식이 맞으면 담아 다시 쓰고, 형식이 틀린 원소만 버린다. 없거나 쓸 원소가 없으면 ["shell"] 로 읽는다. 대소문자만 다른 항목을 합치면 출처도 합집합이다. 항목 안의 모르는 필드는 보존하지 않는다.
  • 가져오기 워터마크(history.importedUntil, #207 · FR-TK-09): (출처, 환경)마다 마지막으로 가져온 시각 {source, env, until}. 없거나 배열이 아니면 빈 맵(이전 파일 호환 — 필드 추가라 schemaVersion 은 2 그대로), 틀린 원소는 버리고 같은 (출처, 환경)이 여럿이면 가장 늦은 시각을 쓴다. 빈 맵이면 키를 쓰지 않는다. WorkHistory.importVisits 는 이 시각보다 늦게 쓴 경로만 새 항목으로 만들므로, 사용자가 지운 경로는 그 뒤에 새 대화가 생길 때만 돌아온다.
  • 틀린 항목: 해석할 수 없는 값(경로 · 환경 · 시각 · visitCount < 1 · 필수 필드 누락)이 있는 항목은 그것만 건너뛰고 알린다. 고정이면서 숨김(고정 우선) · 처음 > 마지막(처음 = 마지막) · 틀린 별칭(별칭만 버림)은 고쳐서 읽는다. 대소문자만 다른 Windows 경로는 하나로 합친다.
  • 한 문서 · 두 부분: 읽기 · 잠금 · 손상 판정 · .bak 복구 · 마이그레이션은 문서 단위로 한 번 한다. 이력 save 든 작업 공간 save 든 두 부분의 마지막 값을 한 번에 원자적으로 쓴다.
  • 다른 최상위 키 · window 의 모르는 필드(예: toolkit.tab): load 때 읽은 것을 저장할 때 그대로 다시 쓴다. 디스크를 다시 읽지 않는다. workspace 안의 모르는 필드는 보존하지 않는다.
  • 마이그레이션: 낮은 버전(없으면 1)은 Migration(from, to) 체인으로 올려 읽고 알린다(Migrated). v1 → v2 는 history 를 그대로 두고, 문자열 lastCwd 의 환경을 프로파일 ID(wsl:<배포판> · powershell · cmd)로 정한다. 정할 수 없으면 workspace 만 버리고 알린다.
  • 부분 손상(workspace · window 값이 틀림): 문서 전체를 손상으로 보지 않고 이력을 살린다. 틀린 창은 트리에서 빼 형제로 축약하고(PanesDropped), 창이 모두 틀린 탭은 버리고, 남는 탭이 없으면 작업 공간 없이 연다(PartDiscarded("workspace")). 포커스가 없으면 첫 창, activeTab 이 범위 밖이면 0. window 가 틀리면 창 상태만 기본값(PartDiscarded("window")). 파일은 옮기지 않는다.
  • 손상(JSON 문법 · 뼈대가 틀림, 상위 버전은 제외): 손상 원본을 옆에 둘 이름은 state.json.corrupt-yyyyMMdd'T'HHmmss'Z'(UTC, 겹치면 -1 …)다. state.json.bak 이 정상이면 원본을 그 이름으로 복사한 뒤 state.json 을 .bak 내용으로 원자적으로 바꾸고 알린다(어느 단계에서 멈춰도 state.json 이 비지 않는다. 실패하면 오류이고 원본은 제자리). .bak 을 읽을 수 없으면(입출력 오류) 아무것도 바꾸지 않고 오류다. .bak 으로 복구하면 이력과 작업 공간을 모두 되살린다. 둘 다 손상이거나 .bak 이 없으면 원본을 그 이름으로 옮기고 빈 이력으로 시작한다. 다른 인스턴스가 쓰는 파일은 건드리지 않는다.
  • 읽기 전용: schemaVersion > 2(history 모양이 달라도 손상으로 보지 않음)이거나 다른 인스턴스가 state.lock(FileChannel.tryLock)을 쥐고 있거나 잠금 파일을 열 수 없으면 읽을 수 있는 만큼 읽고 저장하지 않는다(파일 · .bak 을 건드리지 않음). 변경은 메모리에만 남는다.
  • 쓰기: UTF-8(BOM 없음, 한글 이스케이프 없음) · 줄바꿈 LF · state.json.tmp → ATOMIC_MOVE. 실패하면 기존 파일은 그대로다.
